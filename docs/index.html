DE LA INTERACCIÓN A LA RESPUESTA

¿Cómo funciona Botty?

En las dos ediciones, el ciclo es parecido: Botty recibe una interacción, decide qué hacer y responde. El hardware disponible y los extras instalados determinan qué funciones están activas.

  1. 01 ◉

    Te recibe

    En Windows puedes escribir, usar el micrófono o tocar la ventana. En el prototipo físico puedes hablar, usar el teclado o un mando; una cámara puede detectar personas y objetos.

  2. 02 ⌘

    Interpreta

    El reconocedor convierte la voz en texto cuando está instalado. Botty resuelve saludos y acciones sencillas directamente; para preguntas abiertas consulta su motor de IA y el contexto de la conversación.

  3. 03 ↗

    Elige una acción

    Puede contestar, cambiar de expresión, buscar información o usar herramientas disponibles. En Raspberry Pi los motores y sensores dependen de los controladores conectados y de la configuración del robot.

  4. 04 ◡

    Te responde

    Los ojos animados acompañan la interacción. Si la síntesis de voz está habilitada, Botty también habla; el prototipo puede guardar recuerdos localmente y mostrar estado y controles en su dashboard web.

EDICIÓN DE ESCRITORIO · WINDOWS

Botty vive en tu pantalla.

La aplicación abre una ventana con sus ojos. Escribe con Enter para escribir y vuelve a pulsarlo para enviar; V inicia una escucha puntual y Esc cierra la aplicación. También puedes hacer clic para provocar una reacción. Con los extras de voz, el micrófono queda escuchando y puedes empezar una frase con “Boti”.

Las respuestas de IA usan un modelo GGUF local si instalas el extra local-ai y colocas un modelo en botty/models/. Sin ese modelo, siguen disponibles las acciones directas, pero no el chat generativo. La búsqueda web, el clima, la apertura de aplicaciones y la lectura OCR se activan con solicitudes reconocidas; la lectura de pantalla requiere Tesseract instalado en Windows.

EDICIÓN FÍSICA · RASPBERRY PI

Botty percibe el entorno.

El programa combina el rostro animado con módulos opcionales de micrófono, cámara, reconocimiento facial y sensores. El bucle principal actualiza la expresión y procesa voz, visión y controles según el equipo conectado.

Para conversar, el motor de IA se configura con Ollama local (predeterminado; modelo qwen2.5:3b) o con OpenAI mediante una clave propia. La búsqueda, la música y el dashboard necesitan sus dependencias y configuración. Los motores y el sonar están deshabilitados por defecto; OLED y aprendizaje por refuerzo también dependen de extras y configuración.

EMPEZAR

Prueba primero en pantalla.

Instala Python 3.10 o superior. Los comandos instalan cada edición por separado. Aunque son el mismo Botty, no comparten instalación ni memoria.

Windows · Botty Desktop repository python -m pip install -e ".[voice]"
botty
Raspberry Pi · Botty Robot repository python -m pip install -e ".[web]"
python -m botty

HERRAMIENTA COMPLEMENTARIA

Prueba el hardware por separado.

Botty Robot Hardware es una consola independiente para comprobar motores, sonar y buzzer en Raspberry Pi. Escribe help para ver comandos como forward, distance, beep y stop. Cada movimiento dura 0,3 s por defecto y puede limitarse a un máximo de 2 s; sin RPi.GPIO, solo funciona en modo simulación.

cd botty-robot
python -m pip install -e .
botty-robot Ver controlador ↗
Antes de mover el robot

Levanta las ruedas al probar. La edición Prototype trae el control de motores desactivado inicialmente; habilítalo solo después de revisar el driver y el cableado. Para el HC-SR04, adapta su eco de 5 V con un divisor o level shifter: una Raspberry Pi usa GPIO de 3,3 V y puede dañarse con 5 V directos.

Datos y privacidad

La memoria de conversación se guarda localmente. El reconocimiento de voz del prototipo puede usar Google; la edición física puede enviar consultas a OpenAI si eliges ese proveedor. Ollama y el modelo GGUF de Desktop pueden ejecutarse localmente. Revisa la configuración antes de compartir datos personales.
